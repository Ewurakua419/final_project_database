# Database Design and Custom Logic Reference (Revised)

This guide documents the database schema revisions and custom business logic (views, stored procedures, functions, and triggers) implemented for the e-commerce platform.

---

## 1. Key Schema Refactors & Enhancements

### ID Field Enlargement (`VARCHAR(36)`)
To avoid potential ID collisions (birthday paradox vulnerability) inherent in `VARCHAR(6)` constraints when using random string identifiers:
* All primary and foreign keys representing entity IDs (e.g., `customer_id`, `vendor_id`, `product_id`, `order_id`, `cart_id`, `payment_id`, `address_id`, `shipping_id`, `delivery_id`) have been upgraded to `VARCHAR(36)`.
* This accommodates full, standard UUIDs generated by the application layer.

### Redundancy Elimination (`orders.cart_id`)
* Storing `cart_id` in the `orders` table was redundant due to the strict 1-to-1 relationship between customers and carts. 
* The `cart_id` column and its foreign key constraint were removed from the `orders` table. Any queries mapping order details to their originating carts now retrieve it dynamically via a `JOIN` with the `cart` table.

### Strict Uniqueness Constraints
* A `UNIQUE` constraint was added to `cart.customer_id` (`uq_cart_customer`) to ensure that a customer cannot own multiple carts at the database level.
* Uniqueness is strictly enforced on `customer.email` and `vendor.email` to prevent duplicate registration.

### Soft Delete & Suspension Support
* **`customer.is_active`** (BOOLEAN, default `TRUE`): Allows administrators to suspend customers, blocking authentication.
* **`vendor.is_active`** (BOOLEAN, default `TRUE`): Allows administrators to suspend vendors, hiding their listings.
* **`product.is_active`** (BOOLEAN, default `TRUE`): Supports soft-deleting products to preserve historic sales statistics.

### Order Dispatch Status
* The text-based `item_status` column in `order_items` was replaced by a boolean `is_dispatched` flag. This tracks vendor fulfillment on an item-by-item level.

## 2. Stored Procedures

### `sp_add_to_cart`
* **Purpose:** Safely inserts items into a customer's shopping cart.
* **Logic:** Checks the requested quantity against the warehouse stock in `product`. Raises a custom error (`SQLSTATE '45000'`) if the quantity is negative, if the product does not exist, or if total quantity (existing + new) exceeds the vendor's available stock.

### `sp_place_order`
* **Purpose:** Transitions items from cart checkout to orders.
* **Logic:** 
  1. Validates that the order ID is unique and that the customer's cart is not empty.
  2. Calculates the order subtotal by summing (`quantity * price`) for all items in the customer's cart.
  3. Inserts a new record in the `orders` table (without mapping `cart_id`).
  4. Populates the `order_items` table with the items, initializing `is_dispatched = FALSE`.
  5. Clears the cart by deleting all matching records from `cart_items`.

### `sp_update_delivery_status`
* **Purpose:** Safely updates delivery states.
* **Logic:** Ensures the new status matches one of the allowed workflow phases (`pending`, `in port`, `on the way`, `delivered`). Raises a custom error if the delivery ID is not found or if the status parameter is invalid.

## 3. Stored Functions

### `fn_calculate_order_total`
* **Purpose:** Calculates the final billing amount for a given order.
* **Logic:** Queries the `orders` table and returns the sum of the order `subtotal` and `shipping_fee`.

### `fn_get_product_average_rating`
* **Purpose:** Returns the aggregate customer rating for a product.
* **Logic:** Computes and returns `ROUND(AVG(rating), 2)` from the `review` table for a given product ID.

## 4. Database Triggers

### `trg_reduce_stock_after_order_item`
* **Execution:** `AFTER INSERT` on `order_items`.
* **Purpose:** Automatically deducts product stock quantities immediately after an order is placed.

### `trg_check_stock` & `trg_check_stock_onupdate`
* **Execution:** `BEFORE INSERT` & `BEFORE UPDATE` on `cart_items`.
* **Purpose:** Ensures customers cannot add or update cart quantities to exceed the available warehouse inventory.

### `trg_set_review_date`
* **Execution:** `BEFORE INSERT` on `review`.
* **Purpose:** Automatically stamps the review record with the current database date (`CURRENT_DATE`).

### `trg_auto_update_delivery_status_to_port`
* **Execution:** `AFTER UPDATE` on `order_items`.
* **Purpose:** Decouples logistics from vendors. It counts non-dispatched items in an order. Once all items are marked `is_dispatched = TRUE` by their respective vendors, it automatically updates the order's `delivery_status` from `pending` to `in port` (ready for courier pickup).

### `trg_evict_cart_items_on_soft_delete`
* **Execution:** `AFTER UPDATE` on `product`.
* **Purpose:** When a product's `is_active` flag is set to `FALSE` (soft delete), this trigger automatically deletes the product from all active customer shopping carts.

### `trg_on_vendor_status_change`
* **Execution:** `AFTER UPDATE` on `vendor`.
* **Purpose:** Handles account suspensions.
  * When a vendor's status changes to suspended (`is_active = FALSE`), this trigger sets all of their products to inactive, cascade-evicting those products from customer shopping carts.
  * When a vendor's status is restored to active (`is_active = TRUE`), the trigger reactivates all of their products, returning them to the active product catalog.
